# 原生图表：选型、场景与调用

使用 `office_pptx.py charts` 查询类型、数据模型、预览要求及每种三个使用场景；`catalog` 同时包含 charts。以下支持范围指创建可编辑的原生图表部件与嵌入式 Excel 数据，不是图片或形状模拟。

## 支持范围与预览

- 经典 PowerPoint 图表枚举全部 73 个变体：柱/条、堆积及百分比堆积、折线、面积、饼/复合饼、圆环、散点、气泡、雷达、股票、曲面，以及经典 3D/圆柱/圆锥/棱锥变体。
- `combination`：柱形、折线、面积系列组合，可按系列选择第二数值轴。
- ChartEx 八类：瀑布、漏斗、直方、帕累托、箱线、矩形树、旭日、填充地图。
- 所有类型均走原生创建、数据校验、嵌入工作簿、保存/重开和更新数据；数据与图表缓存须一致。类型转换保留位置、层级和稳定 ID，不替用户编造坐标、气泡尺寸、层级关系或 OHLC 数据。
- 传统 2D 图优先；3D、圆锥、圆柱和棱锥仅用于用户指定或延续原模板，避免透视影响数值比较。
- ChartEx 需要支持相应图表的 PowerPoint（Office 2016+；具体类型与安装版本有关）。当前 LibreOffice 对部分高级图表显示“不支持”、省略图形或近似成其它类型；曲面图及量价股票图也需在 PowerPoint 核对。系统会将这些类型标记为预览未验证，并跳过把不完整截图当成真实图表的视觉审查。**文件原生结构通过检查不等于 PowerPoint 视觉验收通过。**
- 地图图表生成地域名称、数值及原生 regionMap 部件。新建图未包含地理边界缓存，地域解析与边界获取依赖 Office 地图服务及网络；不能承诺离线完成地图绘制。需要离线地域图时优先复用有边界缓存的用户模板，并在 PowerPoint 验证。

## 数据格式

原子操作外壳：

```json
{
  "presentation_id": "deck",
  "operation_id": "add-chart-01",
  "base_revision": 2,
  "slide_id": "p01",
  "operation": "element.add_chart",
  "element": {
    "id": "revenue-chart",
    "geometry": {"x": 0.1, "y": 0.25, "w": 0.8, "h": 0.6},
    "chart": {
      "type": "column_clustered",
      "categories": ["Q1", "Q2", "Q3"],
      "series": [{"name": "收入", "values": [12, 18, 25]}],
      "unit": "亿元"
    }
  }
}
```

下表中的对象放入 `element.chart`。使用模板内容区时也可用 anchor 代替 geometry。

### 分类图、柱/条、折线、面积、饼、圆环、雷达、曲面

```json
{"type":"doughnut","categories":["产品 A","产品 B","产品 C"],"series":[{"name":"收入","values":[40,35,25]}]}
```

1–12 个非空命名系列、1–2000 个分类，值必须有限且与分类等长；仍受单个原子请求 30 KB 上限约束。大量点先按业务口径聚合，不能擅自抽样。饼/复合饼限单系列，圆环可有多圈；占比图要求非负且总和为正。曲面至少 2 个系列 × 2 个分类，输入必须是同一坐标网格的测量值。绘图数据不在三个维度上时不要为了外观使用曲面图。

### 散点与气泡

```json
{"type":"scatter","series":[{"name":"样本 A","points":[[10,2.1],[20,3.4],[35,5.8]]}]}
```

```json
{"type":"bubble","series":[{"name":"产品","points":[[10,2.1,100],[20,3.4,300],[35,5.8,200]]}]}
```

points 分别为 `[x,y]` 与 `[x,y,size]`，每系列可有不同的 X 坐标和点数；尺寸非负。不要用分类字符串代替真实数值 X，也不要把 size 当作半径手工开方；由原生图表处理气泡尺寸。分类图转换到坐标图需先有明确的数据模型，不能自动补序号或尺寸。

### 组合图与双轴

```json
{"type":"combination","categories":["Q1","Q2","Q3"],"series":[{"name":"收入","type":"column","values":[12,18,25]},{"name":"增长率","type":"line","secondary_axis":true,"values":[0.1,0.18,0.22]}]}
```

每个系列的 type 可选 column/bar（旧别名，均为竖向柱）、column_clustered/column_stacked/column_stacked_100、line/line_markers、area/area_stacked。至少两个系列，至少一个在主轴。第二轴适用于不同单位或数量级，必须在标题或说明中标明口径，避免双轴制造虚假相关。更换已有组合图数据时保留各系列 type/secondary_axis。

### 股票与量价

```json
{"type":"stock_ohlc","categories":["11-01","11-02"],"series":[{"name":"Open","values":[10,11]},{"name":"High","values":[13,14]},{"name":"Low","values":[9,10]},{"name":"Close","values":[12,13]}]}
```

HLC 顺序为 High、Low、Close；OHLC 为 Open、High、Low、Close；VHLC/VOHLC 在前面加 Volume。量价图有两个数值轴，不能把成交量与价格堆在同一标度。校验 Low ≤ Open/Close ≤ High，Volume 非负。

### 瀑布、漏斗、直方与帕累托

```json
{"type":"waterfall","categories":["期初","新增收入","成本增加","期末"],"series":[{"name":"金额","values":[100,40,-15,125]}],"totals":[0,3]}
```

totals 是从 0 开始的合计/小计点索引；合计值由用户数据给出，不重复当成增量累加。正增量、负增量、合计统一使用整稿设计色板的正向色、负向色和强调色。

```json
{"type":"funnel","categories":["访问","注册","试用","付费"],"series":[{"name":"人数","values":[10000,2500,700,180]}]}
```

阶段顺序来自实际流程，不自动排序或强制单调；需要转化率时说明分母，不能混用各阶段人数与百分比。

```json
{"type":"histogram","categories":["样本1","样本2","样本3","样本4","样本5"],"series":[{"name":"耗时毫秒","values":[12,18,18,25,60]}],"bin_count":5}
```

输入原始观测值，categories 仅标识观测记录；bin_count 与 bin_size 二选一，默认 10 个箱。不要把已分箱频数当原始样本；已经分箱的频数使用柱形图。点数很少时不要用直方图解释总体分布。

```json
{"type":"pareto","categories":["超时","鉴权失败","参数错误"],"series":[{"name":"失败次数","values":[120,45,20]}]}
```

使用非负类别计数/金额，原生布局负责降序柱与累计贡献折线；累计线复用柱系列数据，不再新增一份假百分比系列。

### 箱线

```json
{"type":"box_whisker","categories":["观测1","观测2","观测3","观测4","观测5"],"series":[{"name":"版本 A","values":[12,18,20,22,65]},{"name":"版本 B","values":[10,14,17,19,23]}]}
```

每系列是一组原始观测，不是预先算好的最小值/Q1/中位数/Q3/最大值；至少四个观测，当前系列等长。采用 inclusive 四分位口径，跨页面统一口径。不要用均值一列数据冒充完整分布。

### 矩形树与旭日

```json
{"type":"treemap","categories":[["华东","产品A"],["华东","产品B"],["华西","产品A"],["华西","产品B"]],"series":[{"name":"收入","values":[40,20,25,15]}]}
```

category 是从根到叶的路径数组，单系列非负叶子权重；不重复输入父级汇总，以免双重统计。旭日改 type 为 sunburst。矩形树强调面积份额，旭日强调层级路径；只比较少数同级值时使用条形或圆环更清楚。

### 填充地图

```json
{"type":"map","categories":["China","Japan","Germany"],"series":[{"name":"客户数量","values":[120,80,65]}]}
```

使用明确、不混层级的地域名称；同名城市应带国家/省份信息。此接口只生成 native regionMap 结构，不附送地理边界，不把地名自动转换成经纬度。PowerPoint 中联网完成地域解析后核对边界与数据。未知地域不能画成任意形状或直接忽略。

## 更新、换型与样式

- `chart.replace_data`：传 slide_id、element_id、完整 chart 对象；不改变图表类型。类型可省略并从现有对象推断，特殊参数如 waterfall.totals 也应随数据一起传入。模板图保留已有绘图样式，生成图同步更新 manifest 的逻辑数据。
- `element.update`：用 element.id 与完整 element.chart 更新生成图；不会给模板的形状拼图创建嵌入工作簿。
- `chart.change_type`：element={"id":"revenue-chart","type":"doughnut"}。仅在现有数据模型满足目标类型时转换。类型专用数据不具备时原子拒绝，不能伪造坐标、层级或成交量。
- 创建与更新均检查数据、图表缓存与 Excel 工作簿。普通类别上限扩展为 2000 点、12 个系列；单请求仍限 30 KB，图表太密时优先按口径聚合或拆页。
- 继承模板配色与字体；系列编码全稿保持一致。支持原生样式接口中的配色、字体、线宽、图例、标签和数字格式；不同图型对标签/坐标轴的显示能力不同，实际效果仍需预览。不要仅因存在某种图型就优先使用。

## 格式依据与验证边界

图表结构参考 [python-pptx 图表类型与实现范围](https://python-pptx.readthedocs.io/en/latest/dev/analysis/cht-chart-overview.html)、[Microsoft ChartEx 布局定义](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-odrawxml/2ea3f228-fe39-4f55-b8ec-cee89596e926) 和 [Microsoft ChartEx ChartSpace](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-odrawxml/416e664f-c6f6-4ed9-914b-4eaaa20724dd)。高级 XML 的子元素、属性和顺序对照 Microsoft Open XML SDK 官方 schema；当前环境没有 PowerPoint，不能将结构校验、工作簿回读或 LibreOffice PDF 导出称为 PowerPoint 实机验收。


## 新建稿的验收入口

已支持的新建统计图由 `native_charts.create` 或 `element.add_chart` 生成；仅缺少对应图型时允许按 `chart_fallbacks` 显式申报自绘，不以形状替代已支持类型。风格 MD/参考图的完整脚本示例见 [style-authoring.md](style-authoring.md)。生成后运行 `office_pptx.py audit-charts files/deck.pptx --request tmp/deck-plan.json`，每页计划声明 page 与 statistical_charts 数量；脚本会检查实际 chart 及嵌入工作簿，不能把形状统计图当作通过。

降级接口：每页 statistical_charts 为统计图总数，chart_fallbacks 为 [{type,reason,element_ids}]；审计分别输出 native_charts、fallback_charts、all_native。已支持图型、无原因或无实际对象的申报不通过。详见 [style-authoring.md](style-authoring.md#不支持的图型显式申报自绘)。
